# UtsavCards

A static Diwali website with a Cloudflare Worker and Razorpay checkout. Free cards have a book opening, fireworks and optional sound; premium offers longer fireworks and HD export. Four designs use distinct backgrounds. Wishes are presets, not AI-generated.

## Test payments
1. Create a Razorpay merchant account and complete required onboarding. Enable Test Mode. Create Test API keys in Razorpay Dashboard → Account & Settings → API Keys. UPI payment methods/QR availability depend on provider, account, checkout and device; verify in test/live rather than assuming a QR is always shown.
2. Connect GitHub to a Cloudflare Worker build. Set the deploy command to `npx wrangler deploy` (repository root); `wrangler.jsonc` deploys site assets and `/api/*`. Enable workers.dev. Use this Cloudflare URL, not GitHub Pages, for checkout.
3. In Cloudflare Worker Settings → Variables and Secrets, add encrypted secrets `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, and `SIGNING_SECRET` (32+ random characters, e.g. `openssl rand -hex 32`). Never put secrets in GitHub. Deploy/redeploy as Cloudflare prompts.
4. `PRICE_PAISE` is 1000 (₹10). Create a premium card and complete a Test Mode checkout. Confirm the checkout opens, captured payment unlocks, and the copied paid link opens in a private browser. Verify failures and cancellation do not unlock. You must enable automatic capture in Razorpay; the Worker only unlocks captured payments. Use test instructions and instruments provided by Razorpay; never use real credentials in test.
5. Before going live, finish merchant activation, check real UPI availability and charges/minimums, replace test keys with live keys as secrets, and thoroughly test using a real low-value payment. No payment is currently active without these account steps.

## Limitations
The server checks the Razorpay signature, fetches the order and captured payment from Razorpay, checks amount and card hash, and issues a signed per-card entitlement. Checkout UI and card visuals are browser code, so determined users can bypass cosmetic premium restrictions. Shared signed links grant access to anyone who has them. Changing SIGNING_SECRET invalidates old links. There is no database, recovery for lost paid links, automatic refund revocation, webhook processing, rate limiting, audit trail, tax support or production-ready customer support. These must be addressed before selling at scale. If a captured payment is not verified because of network problems, contact the seller with the payment ID rather than paying again.

Card data, including optional photo, is in the URL without encryption. Links may be too long for browsers or messaging platforms, and may appear in server logs or history. Anyone with the link can read the data. Avoid sensitive information. Tailwind, fonts, html2canvas and Razorpay checkout load from external CDNs.

## UPI QR
The premium page can request a single-use, fixed-amount UPI QR via Razorpay. Razorpay must enable the QR Codes product for the merchant account; having checkout API keys alone may not be sufficient. The Worker associates the QR with the card hash and checks the QR's captured amount/count with Razorpay before issuing access. The browser checks periodically and also offers a manual status check. It remembers an active QR in the current tab's session storage for refresh recovery. Keep the tab open and do not pay again if status is delayed; contact support with the transaction details. There is no durable order store, webhook or recovery across browsers/devices. Test QR availability and test-mode limitations with Razorpay; do not scan a test QR with a real UPI app. This is not a complete production payment system.
